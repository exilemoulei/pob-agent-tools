# Architecture

How pob4agents is built and the contracts it keeps. Read this before changing code; [AGENTS.md](../AGENTS.md) has the commands and the short rules. When this doc and the code disagree, the code wins and this doc gets fixed in the same change.

## How a command runs

```text
pob <command>  (L4 cli*.py)
  -> daemon on 127.0.0.1, HTTP/JSON with X-PoB-Token  (L3 daemon/)
    -> BridgeWorker, NDJSON over stdin/stdout  (L1 bridge_client.py)
      -> Windows: pob-zh.exe --engine-headless running PobTools-zh's bridge.lua
         macOS / Linux: LuaJIT 2.1 + lua-utf8 running lua/headless_runner.lua, which boots PoB and loads the same bridge.lua
```

- The CLI starts the daemon in the background on first use (the frozen `pob.exe` through a hidden `pob _daemon` command), or `pob serve` runs it in the foreground. The daemon writes `daemon.json` (`pid`, `port`, `token`) and keeps one engine worker per named build slot (`--target <slug>`, default `POB_SLOT` or `main`).
- What-if commands snapshot the build with `export_code` / `import_code` and roll back afterwards (`snapshot.py`); `--apply` keeps the change and pushes it on the undo stack.
- `pob data` and `pob ground` do not need the daemon: they query a SQLite index built from the engine's Lua data (`game_data/`).

## Modules and layers

`pob_cli/src/pob_cli/` is a strict five-layer DAG: a module imports from its own layer or below, never above, and there are no import cycles. `pob_cli/scripts/arch_lint.py` (`LAYER_MAP`) enforces it, together with the size budgets: every file at most 650 lines and 24,000 bytes, every function at most 200 lines.

| Layer | Modules | Role |
|---|---|---|
| L0 | `errors.py`, `ticks.py`, `guardrails/` (incl. `reply_patterns.py`, `reply_scanner.py`) | Foundation and static rules: error types, tick math, PoE2 guardrails, reply scanning for hooks |
| L1 | `updater/`, `bridge_protocol.py`, `bridge_client.py`, `importers.py`, `game_data/`, `external_data/`, `poedb_client/`, `turn_receipts.py` | Engine runtime and data sources: engine install and updates, the bridge to the engine, build import, local game data, poe.ninja / wiki / PoEDB clients, the hook receipt ledger |
| L2 | `formatters/`, `snapshot.py`, `analyzer/`, `mutators/`, `comparator/`, `bench/`, `item_inspect.py`, `trade_craft.py`, `trade_item/`, `trade_client/`, `trade_query/`, `trade_eval/`, `timeless/` | Domain core: rendering, what-if transactions, audits, build edits, comparison, crafting bench, trade, timeless jewels |
| L3 | `daemon/` | The daemon server and its client |
| L4 | `cli.py`, `cli_common.py`, `cli_lifecycle.py`, `cli_build_io.py`, `cli_inspect.py`, `cli_inspect_parts.py`, `cli_mutate_items.py`, `cli_mutate.py`, `cli_optimize.py`, `cli_self_update.py`, `cli_data_render.py`, `cli_data.py`, `cli_trade/`, `cli_timeless.py`, `cli_hook/` | Command-line entry points |

Bundled with the package: `data/bench_costs.json` (generated by `pob_cli/scripts/update_bench_costs.py`) and `lua/headless_runner.lua`. Outside the package: the cross-harness agent skill `skills/pob/SKILL.md` (with `references/`) and the hook configs `hooks/hooks.json` (Antigravity) and `hooks/claude-hooks.json` (Claude Code).

## Engine and paths

Engine lookup (`updater.resolve_engine_root`):

1. `POB_ROOT`, if it is a valid engine.
2. `<POB_RUNTIME_DIR>/engine`. The default runtime dir is `<repo>/.runtime` in a source checkout, `%LOCALAPPDATA%\pob4agents` for an installed or frozen Windows build (falling back to a legacy `%LOCALAPPDATA%\pob-agent-tools` that already has runtime data), and `${XDG_DATA_HOME:-~/.local/share}/pob4agents` on macOS and Linux.
3. A read-only legacy seed: `POB_LEGACY_DIR` or `<repo>/PobTools[20261102]`. Never write to it. In PowerShell always pass that path with `-LiteralPath` (the brackets are wildcards), and the engine's working directory must be its `PoE1` folder.

`pob bootstrap` installs the managed engine from PobTools-zh and PoB master (or seeds it with `--from-dir`); `pob update` applies incremental SHA1-checked updates and hot-reloads live daemon slots. Updates run a `gate_result` smoke probe and roll back from `.bak/` when it fails.

pob updates itself separately (`updater/self_update.py`, `cli_self_update.py`). On an interactive terminal, a command ends with a stderr line when a newer release exists; it reads `<POB_RUNTIME_DIR>/pob_release_check.json`, which a detached `pob _release-check` refreshes at most once a day from the `/releases/latest` redirect, so no command waits on the network for it (off for `hook`, `serve`, `--offline`, `POB_OFFLINE=1` and `POB_NO_UPDATE_NOTICE=1`). `pob self-update` replaces a standalone build in place after the release's signed `SHA256SUMS.txt` and the build's SHA-256 verify and the new build runs: on macOS and Linux by swapping the build directory, on Windows through a detached PowerShell step that swaps it once `pob.exe` exits. Scoop, uv, pipx, pip and source installs get their own update command instead (`pob self-update --check` prints it).

On macOS and Linux, bootstrap also installs `engine/bin/luajit` and `engine/bin/lua-utf8.so` (`updater/posix_runtime.py`), taking the first that works: the copy inside a standalone build (`_internal/runtime/bin`); `pob4agents-runtime-<version>-<platform>.tar.gz` from this pob's release, then the latest one, trusted only through that release's signed `SHA256SUMS.txt`; or a local compile of LuaJIT and lua-utf8 from source tarballs pinned by SHA-256 (`constants.py`, and `build_posix_runtime.sh`, which a test keeps equal). Each candidate must pass a self-test (`+=`, `..=`, `require("lua-utf8")`) first. pob before 0.9 asked for `pob-runtime-<platform>.tar.gz` without any check; no release publishes that name, so those versions keep compiling.

Runtime state in `<POB_RUNTIME_DIR>/`: `daemon.json`, `update_state.json`, `slot_<slug>.json`, `turn_receipts.jsonl`, `hook_turn_<hash>.json`, and a shared `cache/` with `gamedata_<pobVer>_<dataVer>.sqlite`, `ninja_*.json`, `poedb_*.json`, `trade_ratelimit.json` and `trade_stats*.json`.

| Variable | Purpose |
|---|---|
| `POB_ROOT` | Explicit engine root |
| `POB_RUNTIME_DIR` | Engine, daemon state and cache root |
| `POB_CACHE_DIR` | Game-data index and online query cache |
| `POB_SLOT` | Default build slot slug |
| `POB_PROXY` / `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` | Proxy for every download and query |
| `POB_GITHUB_MIRROR` | Mirror prefix for GitHub downloads in `bootstrap` / `update` |
| `POB_OFFLINE=1` | Skip update checks (same as `pob --offline`) |
| `POB_NO_UPDATE_NOTICE=1` | No "pob X is available" line on interactive terminals |
| `POB_LEGACY_DIR` | Read-only legacy PobTools seed |
| `POB_LOCALE` | Engine UI locale for `pob-zh.exe` (default `zh-rTW`, see below) |
| `POB_HOOK_DISABLE_RECEIPTS=1`, `POB_HOOK_DISABLE_V5=1`, `POB_HOOK_SESSION_ID` | Hook receipts, the V5 research gate, and per-session isolation |

| `POB_TEST_PERF_SLACK` | Tests only: multiplies timing budgets on slow CI runners |

## Chinese locales

`pob-zh.exe` shows Traditional names (`zh-rTW`) unless `POB_LOCALE` or `pob-zh.ini` pick another locale, while the local dictionary (`zh-rCN`) and most queries are Simplified. The two translations often word the same thing differently (Mageblood is 法师之血 in zh-rCN and 魔血 in zh-rTW), so engine-facing matching does two things:

- Both sides are folded to Simplified with `game_data.fold_han` (mutator search folds, `analyzer/calcs.py`, class and ascendancy, item DB, gems).
- A Chinese entity name that still finds nothing is retried by its English name from `game_data.english_for_zh`, because the engine always carries the English name.

`game_data/tables_han.py` is generated from Unicode's Unihan data by `pob_cli/scripts/gen_han_fold.py <Unihan.zip>`; hand-picked PoE terms in `tw_norm.py` override it.

## Hard constraints (`R1`..`R13`)

### Engine RPCs

`arch_lint.py` (`[blocked-rpc]`) rejects these outside `bridge_client.py` / `bridge_protocol.py`:

- `R1` `compare_*`: compare builds with two slots through `comparator/`.
- `R2` `sidebar_breakdown`: allowed only when the runtime reports `caps.sidebarBreakdown == True`; otherwise use `get_calcs` + `calcs_breakdown`.
- `R3` `config_mod_search` / `config_mod_add`: use `list_config` / `set_config` / `set_custom_mods`.
- `R4` `set_pob_options` / `oauth_logout`: never change PoB's `Settings.xml`; every boot starts with `new_build{}`.
- `R7` `import_from_uri`: it rejects non-ASCII and parentheses; import through `importers.py`.
- `R11` `save_build_as`: the CLI writes files to disk itself.

### Numbers

- `R5`: every DPS, EHP and other build number comes from the headless engine. Never estimate one in Python or read one out of build XML.

### Reliability (`R8`..`R12`)

- `R8`: `BridgeWorker` uses an `RLock`, drains `stderr`, heals the `import_code` `b:Shutdown()` deadlock (`new_build{}`, then restore `last_good_code`) and flags `treeVersion` mismatches.
- `R9`: colour codes (`^xRRGGBB`, `^0`..`^9`) are stripped only in `formatters/`, keeping the raw keys.
- `R10`: the daemon listens on `127.0.0.1` only and requires `X-PoB-Token`.
- `R12`: `tree_click` checks `allocatedNodes` before every click; anoints validate against `notableDB` first.
- Dewatering disables `customMods` per group in place (`enabled=False`) and appends the sentinel `{"title":"pob-cli dewater","text":"# disabled","enabled":True}`; it re-applies `presetBossSkills` after `enemyIsBoss`, defaults Vaal gems to `enableGlobal1=False` (Vaal burst) and `enableGlobal2=True` (base skill), and proves read-only rollback with `verify_restored`.

### Engine and updater red lines

- Never commit the 1 GB `PobTools` pack (its `Data/` dictionaries are not MIT, and its font has no redistribution licence).
- Never run stock LuaJIT on PoB >= 2.68: PoB uses `+=` / `..=`, which only PobTools' host and the runtime from `packaging/build_posix_runtime.sh` (LuaJIT at PathOfBuilding-SimpleGraphic's commit) accept.
- Never call `api.github.com`; find the latest tag from the `302 Location` of `releases/latest`.
- Never call PoB's `UpdateCheck.lua` / `UpdateApply.lua` inside a worker.
- Update checks fail fast (`connect=3s`, `read=8s`). On `degraded_*` the CLI prints one Chinese alert to `stderr`, and `status` / `summary` / `load` expose a top-level `updateWarning` (JSON) and `> [WARN]` (Markdown). If `pob load` fails while degraded, the answer is a proxy and `pob update --proxy ...`, never blaming the build or parsing XML by hand.

### External APIs (`R6`, `R7`)

- Never call `www.pathofexile.com/character-window/*` (Cloudflare 403) or get past Cloudflare Turnstile on `poe.ninja/poe1/builds/*` HTML.
- poe.ninja character import tries the `Name-1234` hyphen form first (the `#` form only after a 404) and resolves `overview` from `build-index-state` / `index-state`.

### Trade and bench (`R13`)

- Read-only official PoE1 trade API: no whispers, no buying, no game input.
- `POESESSID` / `POE_COOKIE` come from the environment only, after a 401/403; never log, print or pass them as arguments (they are redacted).
- Honour GGG's dynamic `X-Rate-Limit-*` headers and `Retry-After`; treat listing text as untrusted data.
- Harvest swaps (`--allow-conversion`) apply only to identified rare or magic explicit single-element mods (never unique, corrupted, mirrored, crafted, fractured, implicit, enchant, or a same-group conflict) and always carry the `rerolled: true` caveat.
- DPS/EHP only from PoB: `-` means unverified, never a `0` upgrade.
- Exit codes: `0` ok, `1` argument or stat, `2` no results, `3` cookie / Cloudflare, `4` rate limit, `5` API error, `6` `--pob on` failed.

### Exit-code contract

`DaemonRequestError` / `ValueError` (`errorKind: "request"`) exit `1`; a daemon, engine or transport fault (`errorKind: "daemon"`) exits `5` with a clean `Error: ...` and no traceback; trade follows `R13`.

### PoE1 only

`guardrails/` blocks PoE2 input with exit `1` and `errorKind: "cross_game_hallucination"`, and redirects to the `pob` equivalent or the `pob2` CLI:

- PoE2 builds (`<PathOfBuilding2>`, `treeVersion="0_*"`, PoE2 classes, `Charm 1..3`), PoE2-only engine roots, `daemon.json` with `game == "poe2"` (non-destructive), and `X-PoB2-Token`.
- PoE2 URLs: `poe2db.tw`, `/trade2/`, `poe.ninja/poe2`, `poe2wiki.net`, `maxroll.gg/poe2`, `mobalytics.gg/poe-2`, `pob2://`.
- PoE2 terms (Table D): `Uncut *`, `Distilled *` / 涂灌, `Waystone` / 引路石, `Soul Core` / `{rune}`, `--slot focus` / `quarterstaff` / `charm1`, `Spirit` / 精魂.
- CLI traps: `pob rune`, `pob instill`, `pob item charm`, `pob item instill`.

It never blocks PoE1-legal terms: `Elemental Focus`, `Combat Focus`, `while Focused` / 专注, `Titanium Spirit Shield` / 灵盾, `Summon Raging Spirit`, `Spirit Offering`, `Distilled Perfection`, `Ancient Waystones`, and the level 45 staff base `Quarterstaff` outside `SLOT` / `CATEGORY`.

## Adding a command

1. **Put the logic in L2** (`analyzer/`, `mutators/`, `comparator/` and so on), on fakes first. Numbers come from the engine, never from a formula of our own (see "Numbers").
2. **Reach the engine through the daemon.** A new engine call is a handler in `daemon/rpc_handlers.py` (or `rpc_mutate.py` for edits) that calls the engine through its `BridgeWorker`, never with an RPC from "Engine RPCs" above. A what-if snapshots and rolls back (`snapshot.py`) unless `--apply` is given.
3. **Add the CLI in L4.** Register it from an existing `cli_*.py` through its `register_*_commands`, or, for a group with heavy imports, add a `cli_<name>` module to `_LAZY_SUBCOMMANDS` in `cli.py` and to the `hiddenimports` of `packaging/pob.spec`. Give a new top-level module its layer in `LAYER_MAP` (`scripts/arch_lint.py`).
4. **Keep the contracts**: exit codes (`1` for a bad request, `5` for a daemon or engine fault), Chinese names folded with `game_data.fold_han`, and PoE2 terms refused by `guardrails/` without blocking a PoE1 term.
5. **Test** offline on fakes, plus a real-engine test that skips without an engine. A new real-engine test raises the ratchets in `engine.yml` in the same change.
6. **Document** every flag in `docs/guides/commands.md` and both READMEs, and the recipe in `skills/pob/SKILL.md` (or its `references/`) when agents should use it.

## Verification

- `python pob_cli/scripts/check.py --fast` (under 3 s): `ruff` on `src`, `scripts`, `packaging` and `tests`, plus the AST checks `[file-budget]`, `[fn-budget]`, `[layer-dag]`, `[blocked-rpc]` and `[spec-sync]` (every lazy subcommand module exists and is bundled by `packaging/pob.spec`).
- `python pob_cli/scripts/check.py --self-test`: five mutation checks in a temp dir proving each rule fires.
- `python pob_cli/scripts/check.py`: the fast gate plus isolated `pytest`, with a ratchet on passed and skipped tests (`--min-passed N --max-skipped N`).
- Real-engine tests find an engine through `POB_ROOT`, `<repo>/.runtime/engine`, then `<repo>/PobTools[20261102]` (`pob_cli/tests/engine_paths.py`) and skip when there is none.

## CI and releases

- `ci.yml` (pull requests and `main`): lint and architecture gate; engine-less tests on Windows, Linux (Python 3.11 floor and 3.14) and macOS; the Windows package build with a no-engine smoke test; the POSIX LuaJIT runtime build; `install.ps1 -SelfTest` on PowerShell 7 and 5.1. The `install.sh` tests (`test_install_sh.py`) run it end to end against a fake signed release on localhost.
- `engine.yml`: bootstraps a fresh engine and runs the full gate on Windows, Linux and macOS, plus the frozen `pob.exe` against the real engine on Windows. It runs nightly through `engine-nightly.yml` (which opens or comments on one tracking issue on failure), on `workflow_dispatch`, on pull requests that change it, and as the release gate.
- `release.yml` (pushing a `v*` tag): `prepare` checks the tag against `__version__` in `pob_cli/src/pob_cli/__init__.py` (the single source) and refuses an already published release; `gate` runs `engine.yml`; `build-python`, `build-windows` and `build-posix` build the wheel, the sdist and the PyInstaller builds without write access (macOS arm64 and x64 on `macos-15` / `macos-15-intel`; Linux x64 and arm64 inside a digest-pinned Debian 12 Python image, so they need glibc 2.36 or newer; each Linux and macOS build carries the LuaJIT runtime and passes `packaging/smoke_frozen.sh`); `assemble` writes `SHA256SUMS.txt`, signs it into `SHA256SUMS.txt.sig` and checks the exact file set and the signature with `pob_cli/packaging/release_tools.py verify`; `publish` attests every file (`gh attestation verify <file> -R exilemoulei/pob4agents`), uploads to a draft, verifies the uploaded copies and publishes (prereleases never become "latest"); `installer` and `installer-posix` install the new tag with `install.ps1` and `install.sh`; `scoop` opens and merges a PR that points `bucket/pob.json` at it; `publish-pypi`, when `vars.ENABLE_PYPI` is set and the release is not a prerelease, publishes `pob4agents` and `pob-cli` to PyPI through trusted publishing (environment `pypi`; each project needs this workflow as its trusted publisher). A failed release is retried with "Re-run failed jobs", which only refreshes the draft. Dispatching on a branch is a dry run of it (gate, build, verify, install the latest release; nothing uploaded), and pull requests that touch release inputs run the same dry run without the engine gate.
- Asset names (`release_tools.py` is the one list): `pob4agents-<version>-<platform>.zip` (Windows) or `.tar.gz` (`macos-arm64`, `macos-x64`, `linux-x64`, `linux-arm64`), each with a version-free alias such as `pob4agents-windows-x64.zip` for `/releases/latest/download/`; `pob4agents-runtime-<version>-<platform>.tar.gz` for macOS and Linux; the `pob4agents-<version>` wheel and sdist (named `pob_cli-<version>` up to v0.8.0). The distribution is `pob4agents` (it was `pob-cli`; the import package stays `pob_cli`), and `pob-cli` on PyPI is a code-free alias built by `release_tools.py shim` that pins `pob4agents==<version>` and provides the same `pob` command; it is never attached to the GitHub release. Build jobs upload release files as `asset-*` artifacts, which is all `assemble` collects. Windows also keeps the names releases up to v0.8.0 used, `pob-v<version>-windows-x64.zip` and `pob-windows-x64.zip`, for saved scripts, pinned versions and README links. `install.ps1` picks whichever name the release's `SHA256SUMS.txt` lists.
- `install.sh` installs the standalone build into `${XDG_DATA_HOME:-~/.local/share}/pob4agents/bin` and links `~/.local/bin/pob` to it (removing an earlier uv or pipx install of `pob-cli`, which would shadow it). When the release has no build for the machine or the build does not run (an older glibc), it installs the release's wheel with uv, pipx or pip, or its sdist when there is no wheel, each checked against the signed `SHA256SUMS.txt`, and stops when the release lists neither; `POB_BRANCH` installs a branch or tag from source on purpose, and `POB_FROM_SOURCE=1` forces the wheel. The old build directory is swapped out only once the new one is in place and runs through the link; a failed swap puts the old one back and stops.
- Release signing: `SHA256SUMS.txt.sig` is the base64 Ed25519 signature of `SHA256SUMS.txt`'s exact bytes, made with OpenSSL from the `RELEASE_SIGNING_KEY` secret, which only tag runs receive (dry runs sign with a throwaway key). The public keys live in `RELEASE_PUBLIC_KEYS` (`pob_cli/src/pob_cli/updater/signature.py`, a standard-library RFC 8032 verifier) `$ReleasePublicKeys` in `install.ps1` (a plain-PowerShell verifier; `install.ps1 -SelfTest` runs the RFC test vectors in CI on PowerShell 7 and 5.1) and `RELEASE_PUBLIC_KEYS` in `install.sh` (OpenSSL 3, or an embedded python3 verifier where OpenSSL cannot; `install.sh --self-test`); tests keep the three lists equal. Both installers accept only a `vX.Y.Z[-pre]` tag and refuse any release after v0.8.0 whose signature is missing or does not verify (a version that does not parse counts as one that needs a signature). Through a GitHub mirror (`POB_GITHUB_MIRROR`), which also picks the tag when none is pinned, every release needs a valid signature, so a mirror can serve files but not change them; releases from before signing install only straight from GitHub. When a release needs a signature and `install.sh` has no Ed25519 verifier (neither OpenSSL 3 nor a usable python3, as on a Mac without the Command Line Tools), it stops before downloading anything and names `xcode-select --install` or `brew install openssl@3`; `POB_SKIP_SIGNATURE=1` lets it go on with HTTPS from GitHub and SHA-256 alone, with a warning, and never applies through a mirror. To create or rotate the key, the owner runs `python pob_cli/packaging/release_tools.py keygen --out <file>` offline, stores the PEM text as the `RELEASE_SIGNING_KEY` secret, and adds the printed public key to all three lists in a commit that is released before the new key signs anything.
- `codeql.yml` (Python and Actions) runs on push, pull requests and weekly.
- Supply chain: every `uses:` is pinned to a commit SHA with a `# vX.Y.Z` comment, bumped by `.github/dependabot.yml` (Actions and the `pob_cli` uv lockfile). CI and release install from `pob_cli/uv.lock` with the interpreter from `setup-python` (`UV_PYTHON_DOWNLOADS=never`); builds run Python 3.14. Workflows default to `contents: read`. Vulnerability reports go through `SECURITY.md` (GitHub private reporting).
