# PoB Agent Tools (`pob`) v0.2 演进与 Swarm 施工方案

本文档基于 2026-11-12 至 2026-11-19 期间真实 PoE 会话审计与上游接口实测制定，作为下一轮启用 `swarm` 并行开发的唯一施工契约。基础架构红线（`R1`..`R12`）见 `v0.1-architecture.zh-CN.md`，若与本文档冲突以本文档为准（其中 `R2` `sidebar_breakdown` 改为按运行期 `caps.sidebarBreakdown` 动态放行；`R6` `poe.ninja` 角色导入契约按第 3.1 节更新）。

## 1. 核心设计决策与防踩坑硬约束

### 1.1 引擎分发底座：按需拉取开源双上游（严禁入库 1GB 整合包，严禁裸跑标准 LuaJIT）
1. **已证实事实**：
   - `PobTools[20261102]` 的宿主 `pob-zh.exe` 与 `Data/bridge/bridge.lua`（`193` 个 RPC）源自开源 MIT 项目 **`Hsiung-Shao/PobTools-zh`**；整合包仅篡改了 `PoE1/UpdateCheck.lua:90`（硬编码 `if true then return "none" end` 锁死在 `2.67.2`），其余 `1,400` 个 `PoE1/` 文件与官方原版 PoB SHA1 100% 一致。
   - **禁止改用标准 LuaJIT + `HeadlessWrapper.lua` 跑原版 PoB**：原版 PoB `>= 2.68.0`（当前 `v2.68.1`）在 `src/Modules/Main.lua:357` 引入了定制语法 `count += 1`，标准 LuaJIT 2.1 直接报语法错误崩溃；且原版 `HeadlessWrapper.lua` 置空了 `Deflate`/`Inflate`/`lcurl`，缺失 `calcs_breakdown`、`node_power`、`gem_search`、`item_tooltip` 及中文物品粘贴反译 `PobToolsReverseText`。
   - **禁止将 `PobTools` 整合包提交进 Git**：整合包重 `1.03 GB`，且 `Data/` 汉化词典（源自 GGG 客户端）非 MIT、`Fonts/FZ_ZY.ttf` 无分发授权。
2. **统一运行时目录与 Bootstrap 流程**：
   - 引擎查找优先级：① 环境变量 `POB_ROOT`（显式指定且含 `pob-zh.exe` 与 `PoE1/`）；② 托管目录 `.runtime/engine`（或 `POB_RUNTIME_DIR/engine`）；③ 本地旧版兼容迁移源 `PobTools[20261102]`（若托管目录尚未初始化且本机存在旧目录，可先将干净宿主文件 `pob-zh.exe`、`engine/`、`Data/`、`Fonts/`、`pob-zh.ini` 种子化拷贝至托管目录，再拉取原版 `PoE1/` 更新，彻底摆脱对旧目录及被篡改 `UpdateCheck.lua` 的依赖）。
   - 全新机器执行 `pob bootstrap [--proxy <url>] [--no-zh] [--from-dir <offline_path>]`（或首次调任意 `pob` 命令触发引导）时，自动下载组装：
     - **宿主与桥接层**：`https://github.com/Hsiung-Shao/PobTools-zh/releases` 最新 `PobTools-<ver>.zip`（约 `50 MB`）及可选双语词典包 `PobTools-DataV2-<N>.zip`（约 `15 MB`，满足 `manifest.minApp` 约束）。
     - **计算脚本与天赋树层（`PoE1/`）**：`https://raw.githubusercontent.com/PathOfBuildingCommunity/PathOfBuilding/master/manifest.xml` 指向的干净原版 PoB（`v2.68.1+`，含 `3_30` 天赋树与 `Reliquarian`）。

### 1.2 每次启动自动检查更新 + GitHub 网络不通显式告警（最高优先级体验红线）
PoB 在赛季初高频日更，且部分地区直连 GitHub（`github.com` / `raw.githubusercontent.com` / `objects.githubusercontent.com`）极易超时、连接重置或 TLS 失败。必须同时满足**每次启动检查更新**与**断网秒级降级 + 双通道明确提示**：

1. **严禁踩的更新死胡同**：
   - **严禁调用 `api.github.com`**（匿名 IP 限流 60 次/小时，实测连续重启即撞 `HTTP 403`）。获取 `PobTools-zh` 最新版本一律请求 `https://github.com/Hsiung-Shao/PobTools-zh/releases/latest`（`follow_redirects=False`，从 `302 Location` 响应头提取 `<tag>`），再下载 `/releases/download/<tag>/PobTools-manifest-<tag>.json`。
   - **严禁在 `BridgeWorker` 内调 PoB 自带 `UpdateCheck.lua` / `UpdateApply.lua`**：Windows 下运行中的 `pob-zh.exe` 会锁死 `lua51.dll`/`SimpleGraphic.dll`，且 `UpdateApply.lua` 会调 `Restart()/Exit()` 打断父子进程管道。
2. **检查时机与增量更新机制**：
   - **每次 Daemon 启动必检**：在 `DaemonManager.start()` 拉起任何 `pob-zh.exe` 子进程**之前**执行版本检查。
   - **长驻守护巡检**：若 Daemon 未退出但距上次检查已超 `30 分钟`，在下次处理 `status`/`load` 请求前自动重检；若有更新，先导出 `main`/`ref` 内存 `export_code`，停掉子进程完成原子替换后再重启子进程并恢复内存构筑。
   - **PoB SHA1 增量更新**：请求 `raw.githubusercontent.com/PathOfBuildingCommunity/PathOfBuilding/master/manifest.xml`（持久化 `ETag` 至 `.runtime/update_state.json` 发 `If-None-Match`，未更新时 `304` 毫秒级返回）。发现新版本时，对比本地 `PoE1/manifest.xml` 的逐文件 `sha1`（强制校验并修复本地与 manifest 不一致的文件如曾被篡改的 `UpdateCheck.lua`），仅并发下载变更文件到 `.staging/`，SHA1 校验全过后备份旧文件至 `.bak/` 并原子替换。
   - **`gate_result` 冒烟门禁与自动回滚**：替换完成后立即跑一次 `pob-zh.exe --engine-headless` 握手，断言收到 `gate_result.ok == true` 与 `hello`；若探针报错，立即回滚 `.bak/` 并记录 `state="degraded_gate_rollback"`。
3. **网络超时预算、代理支持与显式提示契约（Agent + 人类双可见）**：
   - **快速失败不卡死**：启动自动检查连接超时硬限 `connect=3.0s, read=8.0s`（单文件下载超时 `20.0s`，支持重试 1 次），绝不允许因 GitHub 不通让 `pob` 命令卡死数十秒。
   - **代理与镜像透传**：原生读取 `POB_PROXY`、`HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`，同时支持 CLI 显式传 `pob update --proxy <url>` / `pob bootstrap --proxy <url>` 以及 `POB_GITHUB_MIRROR`（可选自定义加速前缀，如将 `https://raw.githubusercontent.com/...` 与 `https://github.com/...` 映射至用户自备镜像）与 `--offline` 跳过检查开关。
   - **双通道显式提示（严禁静默吞错）**：
     - 每次检查结果写入 `.runtime/update_state.json` 并挂载到 `DaemonManager.update_status`：
       ```json
       {
         "state": "up_to_date | updated | degraded_network_error | degraded_gate_rollback | bootstrap_missing",
         "localPobVersion": "2.67.2",
         "remotePobVersion": null,
         "pobToolsVersion": "1.8.1",
         "dataVersion": "data-19",
         "checkedAt": 1795106600.0,
         "networkError": "ConnectTimeout: raw.githubusercontent.com timed out after 3.0s",
         "userHint": "GitHub 连接失败，PoB 未能检查/更新至最新版（当前本地版本 2.67.2，可能缺失最新赛季天赋树或技能改动）。请检查网络代理（设置环境变量 HTTPS_PROXY 或执行 `pob update --proxy http://127.0.0.1:<port>`），或使用 `pob bootstrap --from-dir <本地目录>` 离线导入。"
       }
       ```
     - **面向人类用户的终端提示（`stderr`）**：当 `state` 为 `degraded_*` 时，Daemon 首次被 CLI 拉起、`pob status`、`pob update`、以及 `pob load` 发生导入失败时，必须在 `stderr` 打印醒目的单段中文告警（含当前本地版本、失败原因与 `--proxy` / `HTTPS_PROXY` 解决命令）。
     - **面向 AI Agent 的结构化提示（`stdout` Markdown 顶栏 + `--json` 字段）**：
       1. `pob status`、`pob summary`、`pob load`（当 `state != "up_to_date" and state != "updated"` 时）在 JSON 返回顶层固定附带 `"updateWarning": userHint`，在 Markdown 输出顶部附带 `> [WARN] <userHint>`（同一 Daemon 周期内每次 `status` 必带；`load` 遇 `treeVersion` 或升华不识别报错时强制追加该原因说明，明确告知 Agent“这是由于 GitHub 网络不通导致本地引擎未更新，请提醒用户配置代理后运行 `pob update`，不要误判构筑代码损坏或违规手撕 XML 计算面板”）。
       2. 若本地完全无可用引擎且拉取 GitHub 失败（`bootstrap_missing`），直接返回非零退出码并输出完整代理/离线安装指引。

## 2. 功能与 Bug 修复清单

### 2.1 P0 止血修复
1. **修复 `import_code` 失败导致槽位永久死锁**（`bridge_client.py`）：
   - 根因：`bridge.lua` 的 `import_code` 先执行 `b:Shutdown()` 再调 `b:Init()`；若 `b:Init()` 因高版本 `treeVersion`（如旧引擎遇 `3_30`）或坏 XML 抛错，子进程未死但内部已无激活构筑，后续所有 RPC 全报 `no build is loaded`。
   - 修复：在 `BridgeWorker.call()` 或 `importers.load_build_into_worker()` 捕获 `import_code` 异常时，立即在同一锁内自动尝试恢复 `self.last_good_code`（若无则调 `new_build{}`），确保槽位 100% 回到可用状态；同时检测 XML 中的 `treeVersion="3_XX"`，若高于本地 `PoE1/TreeData` 最高版本，在异常信息中直接指明版本差与 `pob update` 提示。
2. **修复 `poe.ninja` 角色页一键导入断链**（`importers.py`）：
   - 根因：① `poe.ninja/poe1/api/data/index-state` 已移除 `snapshotVersions` 字段；② `poe.ninja/poe1/pob/raw/overview/code` 要求 `account` 保留 URL 中的连字符 `Song_ycs-4781`（当前代码第 105 行将其替换为 `Song_ycs#4781` 必返 `404`）。
   - 修复：保留 `raw_account` 原样请求（仅在 `404` 时用 `#` 格式兜底重试一次）；从 `https://poe.ninja/poe1/api/data/build-index-state`（`leagueBuilds`）及 `index-state`（`buildLeagues` / `oldBuildLeagues`）解析 `leagueUrl` 作为 `overview` 参数（依次尝试 `type="exp"` 与 `"depthsolo"`）。
3. **固化 `formatters.fmt_num` 字符串哨兵修复**：保留并单测覆盖 CI 构筑 `ChaosMaximumHitTaken="inf"` 场景。

### 2.2 `poe.ninja` 与 `poedb.tw` 高频调用优化 + 本地 0ms 数据库

   - 新增 `pob meta [--league L] [--skill S] [--class C]`：读取无 CF 拦截的 `poe1/api/data/build-index-state` 输出全服构筑总数、主流升华+主技能占比及趋势（注：`/poe1/builds/*` 网页受 Cloudflare Turnstile 保护，严禁在代码中绕过验证挑战；批量角色对比走已知角色 URL 列表 + `pob load`）。

### 2.3 高阶构筑检视与原位编辑补齐
1. **`pob config list` 与 `pob config set --append-mods`**：补齐读取当前非默认 Config 项及 `customMods` 原文的能力；支持在不覆盖原构筑 `customMods` 的前提下追加试算词条。

6. **`pob matrix` 多工况横向试算**：支持一次传入多组预设/覆盖项（如 `Original`、`Pinnacle`、`Uber`、`FlasksOff`、自定义 `MultiplierWitheredStackCount=15`）在同一内存事务循环内批量输出攻防对比表。
